本文是一份面向零基础用户的 macOS 个人博客搭建指南，参考了以下几篇教程，其中部分操作原本面向 Windows：

> 参考 1：[Obsidian + Hugo：我的博客笔记工作流](https://zhuanlan.zhihu.com/p/4791867594)  
> 参考 2：[Hugo + PaperMod + GitHub Pages 搭建一个完善的个人博客（以 Windows 11 为例）](https://psaaa.github.io/jakelove.github.io/posts/build-a-blog-using-hugo-papermod-github-pages/)  
> 参考 3：[Hugo + PaperMod 从零搭建教程](https://suxilan.github.io/notes/start-hugo-papermod/)

笔者根据个人需求整合了这三篇博文。我平时习惯用 Markdown 写零散笔记，也已经在 Typora 中配好了 PicGo + 阿里云 OSS 图床，因此希望博客做到：

- 以展示内容为主，减少对个人履历的强调；
- 使用 Markdown 编辑；
- 能快捷新建文章、推送更新；
- 便于系统地管理博文；
- 无需额外付费注册域名；
- 界面美观易读。

最终采用的方案是：Obsidian + Hugo + Stack + GitHub Pages。最初参考的是使用 PaperMod主题的教程，后来为了侧栏、文章卡片和目录布局，选用了Stack主题。本文直接从 Stack 开始，不需要先安装 PaperMod，也不要求已有 Typora 或图床。

可以按正文手动操作，也可以把全文交给 agent，并附上文末的执行要求。本文使用 **Hugo 0.159.2 Extended + Stack v4.0.3**。

## 1. 准备工具

以下是本文使用的工具：

| 工具 | 功能 |
| --- | --- |
| Obsidian | 编辑、管理 Markdown 文档 |
| Hugo | 把 Markdown、主题和配置生成网页 |
| Stack | Hugo 主题，决定网站的布局与样式 |
| PicGo + 阿里云 OSS | 上传、存放图片，生成可插入 Markdown 的链接 |
| Git + GitHub | 记录修改，并保存网站源文件 |
| GitHub Actions + Pages | 在云端构建网站，再对外提供访问 |
| Giscus | 通过 GitHub Discussions 承载评论 |

日常使用流程是：**新建笔记 → 写作与插图 → 本地预览 → 提交并推送 → 自动构建发布**。

首次搭建按正文顺序进行。图床与评论是可选功能，可以先跳过，完成纯文字博客的上线。

### 1.1 注册账号并安装应用

1. 注册 [GitHub](https://github.com/) 账号。后文的 `YOUR_USERNAME` 都替换成这个账号的用户名，不是 Mac 登录名。
2. 准备代码编辑器；没有的话推荐 [Visual Studio Code](https://code.visualstudio.com/)。下文的文件、文件夹都可以在 VS Code 左侧文件列表中右键新建。
3. 安装 [Obsidian](https://obsidian.md/download)，用于写文章。
4. 安装 [GitHub Desktop](https://desktop.github.com/)，登录同一个 GitHub 账号，按初次启动提示设置 Git 姓名和邮箱；邮箱可选 GitHub 账号设置提供的 noreply 地址。

按 `Command + 空格` 打开 Spotlight，搜索“终端”。下文的 Bash 命令在终端执行，YAML、Markdown 和 SCSS 代码则写入指定文件，不要混用。

### 1.2 安装 Git 和 Hugo

先在终端检查 Git：

```bash
git --version
```

如果系统提示安装开发者命令行工具，按提示完成。没有出现提示且 Git 不可用时，运行 `xcode-select --install`，安装后重新打开终端检查。

打开 [Hugo 0.159.2 下载页](https://github.com/gohugoio/hugo/releases/tag/v0.159.2)，在 Assets 中下载 `hugo_extended_0.159.2_darwin-universal.pkg`，双击完成安装。这个包适用于 Intel 和 Apple 芯片的 Mac。Hugo 是命令行工具，不会出现普通应用那样的编辑窗口。

重新打开终端运行 `hugo version`，确认输出包含 `0.159.2` 和 `extended`。

## 2. 创建新的 Hugo 项目

以下示例把项目放在“文稿”中的 `MyHomepage`。若已有同名文件夹，请换一个新名字，并同步修改后续路径，不要覆盖原项目。

```bash
cd ~/Documents
hugo new site MyHomepage --format yaml
cd MyHomepage
git init -b main
```

这会创建站点、生成 `hugo.yaml`，并初始化 `main` 分支。在同一个终端中继续安装 Stack，固定主题版本：

```bash
git submodule add --depth=1 https://github.com/CaiJimmy/hugo-theme-stack.git themes/hugo-theme-stack
git -C themes/hugo-theme-stack fetch --depth=1 origin tag v4.0.3
git -C themes/hugo-theme-stack checkout --detach v4.0.3
```

用 VS Code 的 `File → Open Folder` 打开 `MyHomepage`。后面的文件都在这个文件夹里创建，完整结构如下；缺少的目录按步骤新建即可：

```text
MyHomepage/                  ← 项目根目录，运行 Hugo 命令的位置
├── hugo.yaml                ← 网站配置
├── .gitignore               ← Git 忽略规则
├── .github/workflows/       ← 自动部署配置
├── assets/img/avatar.jpg    ← Stack 头像
├── assets/scss/custom.scss  ← 自定义样式
├── static/fonts/            ← 自托管字体，可选
├── content/                 ← Obsidian 打开的库
│   ├── notes/               ← 学习笔记
│   ├── posts/               ← 随笔文章
│   ├── _templates/          ← 新文章模板，不发布
│   ├── about.md
│   ├── archives.md
│   └── search.md
└── themes/hugo-theme-stack/ ← 主题子模块，不直接修改
```

这里的“项目根目录”指 `MyHomepage`，“Obsidian 库根目录”指 `content`。下文文件路径默认相对于项目根目录；只有 Obsidian 插件设置中的路径相对于 `content`。

### 写好忽略规则

在项目根目录新建 `.gitignore`，写入：

```gitignore
/public/
/resources/_gen/
/.hugo_build.lock
.DS_Store
/content/.obsidian/
/content/.trash/
/content/_attachments/
```

它避免把生成的网页和 Obsidian 本机设置提交到仓库。文件名不能是 `.gitignore.txt`；Finder 中按 `Command + Shift + .` 可显示这类隐藏文件。

## 3. 配置首页、栏目和阅读样式

新建 `assets/img` 文件夹，把一张 JPG 头像复制进去并命名为 `avatar.jpg`。如果暂不放头像，删除下方配置中的 `avatar` 一行。

打开项目根目录自动生成的 `hugo.yaml`，替换为以下内容，修改 `YOUR_USERNAME`、博客标题和副标题。所有 YAML 缩进都使用空格，不使用 Tab。

```yaml
baseURL: "https://YOUR_USERNAME.github.io/"
title: "我的博客"
theme: "hugo-theme-stack"
defaultContentLanguage: "zh"
locale: "zh-CN"
hasCJKLanguage: true
timeZone: "Asia/Shanghai"
pagination:
  pagerSize: 10
ignoreFiles:
  - '(^|/)\.obsidian(/|$)'
  - '(^|/)\.trash(/|$)'
  - '(^|/)_templates(/|$)'
  - '(^|/)_attachments(/|$)'
permalinks:
  page:
    notes: "/notes/:slug/"
    posts: "/posts/:slug/"
taxonomies:
  category: categories
  tag: tags
params:
  mainSections: [notes, posts]
  sidebar:
    subtitle: "记录学习、思考与成长"
    avatar: "img/avatar.jpg"
  article:
    math: true
    toc: true
    readingTime: true
  widgets:
    homepage:
      - type: search
      - type: categories
      - type: tag-cloud
    page:
      - type: toc
  colorScheme:
    toggle: true
    default: light
  comments:
    enabled: false
menu:
  main:
    - {name: "首页", url: "/", weight: 10, params: {icon: home}}
    - {name: "笔记", url: "/notes/", weight: 20, params: {icon: categories}}
    - {name: "随笔", url: "/posts/", weight: 30, params: {icon: messages}}
    - {name: "关于", url: "/about/", weight: 40, params: {icon: user}}
    - {name: "归档", url: "/archives/", weight: 50, params: {icon: archives}}
    - {name: "搜索", url: "/search/", weight: 60, params: {icon: search}}
markup:
  goldmark:
    extensions:
      passthrough:
        enable: true
        delimiters:
          block: [['$$', '$$'], ['\[', '\]']]
          inline: [['$', '$'], ['\(', '\)']]
    renderer:
      unsafe: true
  highlight:
    noClasses: false
caches:
  images:
    dir: ":cacheDir/images"
```

`unsafe: true` 用于保留文章里的 HTML，例如后文的 `<img>`。这也意味着应只发布自己检查过的 HTML，不粘贴来源不明的脚本。公式配置参考 [Hugo Markdown 渲染设置](https://gohugo.io/configuration/markup/)。

新建 `content/about.md`，在文件头后填写简介、教育经历、项目和成果：

```markdown
---
title: "关于"
url: "/about/"
draft: false
toc: true
comments: false
---

## 简介

在这里填写个人介绍。
```

新建 `content/search.md`：

```yaml
---
title: "搜索"
layout: "search"
url: "/search/"
outputs: [HTML, JSON]
draft: false
comments: false
---
```

新建 `content/archives.md`：

```yaml
---
title: "归档"
layout: "archives"
url: "/archives/"
draft: false
comments: false
---
```

文件应从 `---` 开始。搜索页不要设置 `build.list: never`，否则 Stack 的搜索组件可能找不到它。

新建 `content/notes/_index.md`，填写栏目名称：

```markdown
---
title: "笔记"
---
```

再新建 `content/posts/_index.md`，内容相同，只将标题改为“随笔”。年份、月份子文件夹不需要额外创建 `_index.md`。

字体与样式放在项目自己的 `assets/scss/custom.scss`，避免主题更新时覆盖修改。例如：

```scss
:root {
  --base-font-family: -apple-system, "PingFang SC", sans-serif;
  --article-font-family: "Songti SC", "STSong", "Noto Serif CJK SC", serif;
  --code-font-family: "SFMono-Regular", Menlo, Consolas, monospace;
  --article-line-height: 1.85;
}
```

如果需要更统一的跨设备字体，可以将有合适许可证的 WOFF2 字体放进 `static/fonts/`，通过 `@font-face` 引用 `/fonts/文件名.woff2`，再填入字体变量。可选字体包括 [LXGW Bright](https://github.com/lxgw/LxgwBright)；保留其许可证。只指定系统字体时，不同设备的显示会有差异。

## 4. 测试与本地验收

在 VS Code 新建 `content/notes/hello.md`，写入：

```markdown
---
title: "第一篇文章"
date: 2026-01-01T12:00:00+08:00
slug: "hello"
draft: false
categories: ["建站"]
tags: ["测试"]
math: true
toc: true
comments: true
---

## 你好，博客

这是第一篇用来检查首页和文章页面的测试内容。

行内公式：$E = mc^2$。
```

将示例日期改为实际日期，不要填未来时间。文件顶部两个 `---` 之间叫作文章元信息，此后才是正文。

在终端运行：

```bash
cd ~/Documents/MyHomepage
hugo server -D
```

浏览器打开 `http://localhost:1313/`。确认首页能看到测试文章，头像、菜单和文章目录正常，再进入搜索页搜索“第一篇”。此时评论尚未配置，不显示评论是正常现象。

验收通过后，在运行 Hugo 的终端按 `Control + C` 停止预览，再运行 `hugo --gc --minify`。没有构建错误则继续下一步；这个正式构建不会包含草稿。

## 5. 配置 Obsidian 写作与文章模板

打开 Obsidian，选择“打开本地仓库 / Open folder as vault”，选中 `MyHomepage/content`。私人笔记另建库，放在博客项目之外；这个库只用于准备公开的内容。

进入“设置 → 文件与链接”，关闭“使用 Wiki 链接”，优先使用标准 Markdown 链接。需要插件时，在“设置 → 第三方插件”中启用社区插件，搜索、安装并启用对应插件；只安装信任的插件。

### 用 QuickAdd 快捷新建文章

在第三方插件界面安装并启用 QuickAdd。用 VS Code 新建 `content/_templates/blog.md`；如果在 Obsidian 中新建，路径则是 `_templates/blog.md`。写入：

```markdown
---
title: '{{VALUE:文章标题}}'
date: '{{DATE:YYYY-MM-DDTHH:mm:ssZ}}'
slug: '{{DATE:YYYYMMDD-HHmmss}}'
draft: true
description: ''
categories: []
tags: []
math: true
toc: true
comments: true
---

## 内容

{{CURSOR}}
```

进入 QuickAdd 设置，新建一个名为“新建笔记”的 Template 类型选项，打开它的设置，填写：

| 设置 | 内容 |
| --- | --- |
| 模板路径 | `_templates/blog.md` |
| 文件名 / File name format | `{{DATE:YYYYMMDD-HHmmss}}-{{VALUE:文章标题}}` |
| 新建位置 | 指定文件夹：`notes/{{DATE:YYYY}}/{{DATE:MM}}` |
| 创建后打开 | 开启 |
| 覆盖已有文件 | 关闭 |

将该选项添加到命令面板（部分版本用闪电图标开关），再到 Obsidian“设置 → 快捷键”搜索该命令并绑定按键。若用 `Command + N`，先解除默认“新建笔记”的同名快捷键。随笔可复制一份设置，把目录改为 `posts/{{DATE:YYYY}}/{{DATE:MM}}`。不同版本的字段名称略有差异，见 [QuickAdd 模板文档](https://quickadd.obsidian.guide/docs/Choices/TemplateChoice/)。

用快捷键试建一篇文章，确认它进入对应年月文件夹，标题与日期已填好，且 `draft: true`。`slug` 决定文章网址，修改标题时保留它。标题若含英文单引号，在 YAML 单引号字符串中要写成两个单引号；文件名避免使用 `/` 等路径字符。

## 6. 添加图片与公式

### 6.1 先选图片存放方式

图床不是必需的，但经常复制图片放入笔记的话我推荐配置一下，其他主流md编辑器基本都支持这个功能，插图会方便很多。本文介绍写得比较简略，如有必要会单开一篇笔记写一下不同的方案。

不用图床时，将图片放到 `static/images/`，文章中写 `![图片说明](/images/example.png)`。图片会随网站发布，但 Obsidian 对这类站点根路径不一定能直接预览。

笔者使用 PicGo + 阿里云 OSS，让编辑器中的图片自动上传并替换为公开链接。

### 6.2 配置 PicGo + 阿里云 OSS（可选）

1. 安装 [PicGo 桌面版](https://github.com/Molunerfinn/PicGo/releases)，按 Mac 芯片选择 Apple Silicon / ARM64 或 Intel / x64 安装包。
2. 注册阿里云账号并开通 OSS，新建一个**只存公开博客图片**的 Bucket，记下 Bucket 名称和地域。先了解存储、请求与外网流量计费。
3. 为图床建立专用 RAM 用户及 AccessKey，仅授予目标 Bucket 图片目录所需的上传权限，不使用主账号密钥或全账号管理权限。权限配置参考 [OSS RAM 策略说明](https://www.alibabacloud.com/help/en/oss/user-guide/ram-policy/)。
4. 为计划公开的图片配置匿名读取权限，写入仍需授权；不要设置“公共读写”。若账户启用了阻止公共访问，先确认其用途，不要为图床贸然关闭整个账户的保护。见 [OSS 访问控制说明](https://www.alibabacloud.com/help/zh/oss/user-guide/permissions-and-access-control-overview)。
5. 在 PicGo 的“图床设置 → 阿里云 OSS”中填写 Key ID、Key Secret 和 Bucket。地域填对应代号，例如北京是 `oss-cn-beijing`，不要填完整域名；存储路径可填 `img/`，末尾保留 `/`。保存并设为默认图床。自定义域名仅在已配置好时填写，详见 [PicGo 配置手册](https://picgo.github.io/PicGo-Doc/zh/guide/config.html)。
6. 在 PicGo 上传一张测试图，用浏览器无痕窗口打开返回的 HTTPS 链接。能直接看到图片、且链接不是短期签名地址，才继续连接 Obsidian。

### 6.3 让 Obsidian 调用 PicGo

在 Obsidian 中安装并启用 [Image Auto Upload Pro](https://community.obsidian.md/plugins/image-auto-upload-pro)。打开插件设置，将上传器选为 PicGo app，开启粘贴图片自动上传；暂不启用网络图片转载或上传后删除源文件。

在 PicGo 设置中开启本地 Server，再把上传地址填入 Obsidian 插件的 `PicGo server`。通常是 `http://127.0.0.1:36677/upload`，以实际端口为准；PicGo 需要保持运行。

分别测试粘贴截图、拖入图片。成功后，文章中应出现标准图片链接：

```markdown
![图片说明](https://你的图床域名/图片路径.png)
```

若仍是本地文件路径或 `![[图片.png]]`，不能据此认定上传成功。自动上传失败时，可先用 PicGo 上传，再粘贴得到的 Markdown 链接。设置说明见 [PicGo 文档](https://picgo.github.io/PicGo-Doc/zh/guide/config.html)。

图床上传和博客发布是分开的，草稿里的图片也可能已经公开。OSS 密钥只保存在上传工具中，不放进笔记或 Git 仓库。我自己体感上使用开销很低，充几块钱用了一两年还没问题，但我不能给所有人打包票orz。

### 6.4 调整图片大小

Typora 常生成下面的 HTML，Hugo 允许原始 HTML 后也能使用：

```html
<img src="https://你的图床域名/example.png" alt="图片说明" style="zoom:50%;" />
```

如果希望图片占正文宽度的一半并居中，可以改为：

```html
<img src="https://你的图床域名/example.png" alt="图片说明"
     style="width:50%;height:auto;display:block;margin:0 auto;" />
```

`zoom:50%` 缩放元素；`width:50%` 按正文容器的宽度计算。实际插图时直接写 HTML，不加代码围栏，否则显示的是代码而非图片。

### 6.5 公式

前面的配置已经开启 Stack 的数学渲染与 Hugo 公式透传。文章中可写进行测试：

```text
行内公式：$E = mc^2$

独立公式：
$$
\int_0^1 x^2\,dx = \frac{1}{3}
$$
```

不需要本机安装完整 LaTeX。

## 7. 发布到 GitHub Pages

### 7.1 建立远程仓库并上传源文件

在 GitHub 网页右上角选择 `+ → New repository`，仓库名填写 `YOUR_USERNAME.github.io`，选择 Public。不要勾选初始化 README、许可证或 `.gitignore`，然后创建仓库。这里存放的是网站源文件，提交后任何人都可能看到它们。

回到终端关联这个空仓库，替换用户名后执行一次：

```bash
cd ~/Documents/MyHomepage
git remote add origin https://github.com/YOUR_USERNAME/YOUR_USERNAME.github.io.git
```

在 **GitHub Desktop 桌面应用**中选择 `File → Add Local Repository`，添加 `MyHomepage`。左侧检查没有密钥、私人笔记和生成的 `public` 文件，填写提交说明 `Initial blog`，点击 `Commit to main`。然后点击 `Publish branch` 或 `Push origin`，将本地分支推送到已经关联的仓库。

刷新 GitHub 仓库网页，确认能看到 `hugo.yaml`、`content` 和主题子模块。到这里仅完成源文件上传，还没有完成网站部署。

### 7.2 设置自动构建与部署

仓库网页进入 `Settings → Pages`，将 Source 设为 **GitHub Actions**。回到 VS Code，新建 `.github/workflows/hugo.yaml`；它不同于根目录的 `hugo.yaml`。整个部署方式参考 [Hugo 官方 GitHub Pages 指引](https://gohugo.io/host-and-deploy/deploy-to-github-pages/)。

保存以下工作流。它在 `main` 分支收到推送后下载主题、用指定版本 Hugo 构建，并部署 `public` 目录。`public` 由 Actions 生成，无需提交到源码仓库。

```yaml
name: Publish Hugo website
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: false
env:
  HUGO_VERSION: "0.159.2"
  TZ: "Asia/Shanghai"
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          submodules: recursive
          fetch-depth: 0
      - uses: actions/configure-pages@v6
        id: pages
      - name: Install Hugo
        run: |
          mkdir -p "${RUNNER_TEMP}/hugo-bin"
          curl --fail --location --retry 3 \
            "https://github.com/gohugoio/hugo/releases/download/v${HUGO_VERSION}/hugo_extended_${HUGO_VERSION}_linux-amd64.tar.gz" \
            --output "${RUNNER_TEMP}/hugo.tar.gz"
          tar -xzf "${RUNNER_TEMP}/hugo.tar.gz" -C "${RUNNER_TEMP}/hugo-bin"
          echo "${RUNNER_TEMP}/hugo-bin" >> "${GITHUB_PATH}"
      - name: Build website
        run: hugo --gc --minify --baseURL "${{ steps.pages.outputs.base_url }}/"
      - uses: actions/upload-pages-artifact@v5
        with:
          path: public
  deploy:
    runs-on: ubuntu-latest
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/deploy-pages@v5
        id: deployment
```

在 GitHub Desktop 再次 Commit 和 Push，把新增的工作流上传。仓库网页进入 Actions，打开最新一次运行，等待 build 和 deploy 都成功。

本地与工作流中的 Hugo 版本应保持一致。正式构建不加 `-D`，否则草稿也可能被发布。

部署成功后，用手机或其他设备浏览器访问 `https://YOUR_USERNAME.github.io/`，确认能看到测试文章。Mac 上的 `localhost:1313` 只是本地预览地址；正式站点不需要 Mac 一直开机。

## 8. 给已上线的博客接入评论（可选）

先完成上一步，确保有可访问的博客和公开仓库，再配置评论：

1. 在该 GitHub 仓库的 `Settings → General → Features` 中开启 Discussions。
2. 打开 [Giscus 配置页](https://giscus.app/zh-CN)，按页面提示安装 Giscus GitHub App，只授权这个博客仓库。
3. 填写仓库名称，选择按 `pathname` 匹配页面；讨论分类选择公告类型的分类，例如 `Announcements`。
4. 从生成结果取得 `data-repo-id` 和 `data-category-id`，分别填入下面的 `repoID` 和 `categoryID`。不要照抄别人的 ID。

在 `hugo.yaml` 已有的 `params:` 下，找到 `comments` 区块（目前只有 `enabled: false`），替换为下面这段。代码已带两个空格的缩进，与 `sidebar`、`article` 同级；不要新建第二个 `params`：

```yaml
  comments:
    enabled: true
    provider: giscus
    giscus:
      repo: "YOUR_USERNAME/YOUR_USERNAME.github.io"
      repoID: "从 Giscus 配置页取得"
      category: "Announcements"
      categoryID: "从 Giscus 配置页取得"
      mapping: "pathname"
      strict: 1
      reactionsEnabled: 1
      emitMetadata: 0
      inputPosition: "top"
      lightTheme: "light"
      darkTheme: "dark_dimmed"
      lang: "zh-CN"
      loading: "lazy"
```

分类名称和 ID 必须对应实际选择。文章文件头也应允许评论，即 `comments: true`。“关于”等页面可单独关闭。Stack 已负责输出评论组件，不需要再把 Giscus 的整段脚本粘贴到每篇文章。

保存配置，完成本地构建检查，再通过 GitHub Desktop Commit、Push。等待部署成功后，打开正式站点的测试文章，滚动到底部，用 GitHub 登录后留言，并到仓库 Discussions 核对。首页文章列表本身没有评论区。

## 9. 配置 Obsidian Git：自动本地提交，手动发布

在 Obsidian 安装 Git 插件（作者 Vinzent）。桌面端插件可以使用上级目录的 Git 仓库，不要在 `content` 内再运行 `git init`。不想增加插件，也可以继续用 GitHub Desktop 提交和推送。

确认 GitHub Desktop 已能正常推送，再把插件设为“每 10 分钟本地提交，手动推送”：

- 自动提交间隔：10 分钟。
- 自动 Push、自动 Pull：关闭；使用分钟数的选项通常设为 `0`。
- `Push on commit-and-sync`、`Pull on commit-and-sync`、`Pull on startup`：关闭。
- 合并策略使用 Merge，冲突策略保留默认；暂不开启推送前压缩提交。

先修改测试笔记，确认本地 Git 历史产生提交，而 GitHub Actions 没有被触发，再长期使用自动提交。设置含义可对照 [Obsidian Git 文档](https://publish.obsidian.md/git-doc/Start%20here)。

GPT说了一堆免责声明供参考：

>本地提交不等于云端备份。Push 会上传所有尚未推送的提交，不只当前文章；公开仓库中的草稿源文件和提交历史也能被阅读，`draft: true` 不提供隐私保护。插件可能同时列出上级项目中的配置修改，提交前一并检查。

## 10. 今后发文步骤

前面的配置只需做一次。我个人基本按这个流程操作：

1. 在 Obsidian 中用自定义快捷键新建笔记。
2. 撰写草稿，勾选 `draft: true`。
3. 检查无误后准备发布，将 `draft` 改为 `false`（取消勾选），确认日期不是未来时间，保存修改。
4. `Command + P` 打开命令面板，搜索 `Source Control`，打开 Git 的更改视图检查文件。
5. 再在命令面板执行 `Git: Commit all changes with specific message`，输入提交说明。
6. 在命令面板执行 `Git: Push`，到 GitHub 仓库的 Actions 页面检查本次 build 和 deploy。
7. 部署成功后，打开正式博客检查文章效果。

带 `Git:` 前缀的是 Obsidian 命令不是终端命令。若插件推送失败，可在 GitHub Desktop 尝试 `Push origin`。修改文章标题时保留 `slug`，避免旧链接和评论匹配失效。

首次发文、改配置，或文章包含复杂公式和 HTML 时，建议在第 3 步先做本地检查：

```bash
cd ~/Documents/MyHomepage
hugo server -D
```

打开 `http://localhost:1313/` 检查效果。按 `Control + C` 停止预览后，运行 `hugo --gc --minify`，确认正式构建无错误，再提交发布。日常只改正文时可以直接推送，但仍要查看 Actions 结果和正式页面。

## 可能遇到的问题

| 问题            | 原因与处理                                           |
| ------------- | ----------------------------------------------- |
| 博客网站没有新文章     | 检查 `draft: false`、日期不是未来时间，以及本次 Actions 是否部署成功。 |
| 文章没有评论        | 检查全局和文章评论开关、Giscus 仓库授权及 ID，并在文章详情页底部查看。        |
| 图片尺寸在编辑器与网站不同 | 检查是否用了编辑器专有语法、是否允许 HTML，以及尺寸是相对元素还是正文容器。        |
| 文件旁边仍有 `M`    | 当前文件还有未提交修改。已有提交推送成功，不代表这些新修改已经上传。              |


本地构建失败看终端日志，推送失败看 Git 报错，云端构建失败则展开 Actions 中的红色步骤。实在不行问GPT大人。
