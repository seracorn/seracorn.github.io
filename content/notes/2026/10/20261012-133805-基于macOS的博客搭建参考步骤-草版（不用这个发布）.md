本文是0基础的macOS个人博客搭建流程总结，参考了Windows上的几个项目。本文档已使用GPT润色。（叠甲）

> 参考1:[Obsidian+Hugo：我的博客笔记工作流](https://zhuanlan.zhihu.com/p/4791867594)  
> 参考2:[Hugo + PaperMod + Github Pages 搭建一个完善的个人博客(以 Windows11 为例)](https://psaaa.github.io/jakelove.github.io/posts/build-a-blog-using-hugo-papermod-github-pages/)  
> 参考3:[Hugo + PaperMod从零搭建教程](https://suxilan.github.io/notes/start-hugo-papermod/)  

笔者基于个人需求整合了一下上述三篇博文内容。由于笔者惯用Markdown进行零散笔记编写，且已在Typora中配置了使用PicGo+阿里云OSS的图床上传方案，我希望博客做到：

- [ ] 以展示内容为主，减少对个人履历的强调；
- [ ] 使用Markdown进行编辑；
- [ ] 能快捷开始撰写、推送；
- [ ] 便于系统性进行博文管理；
- [ ] 无需为个人博客额外付费注册域名；
- [ ] 界面美观易读。

因此笔者最终采用的方案是：Obsidian + Hugo + Stack + GitHub Pages。Hugo中有不同主题可以使用，最初参考的是使用PaperMod主题的教程，后来根据想要的侧栏、文章卡片和目录布局换成了Stack主题。

## 1. 各工具功能介绍

| 工具                     | 功能                         |
| ---------------------- | -------------------------- |
| Obsidian / Typora      | 编辑本地 Markdown 文件           |
| Hugo                   | 把 Markdown、主题和配置生成网页       |
| Stack                  | Hugo模版，提供网站布局、样式、目录和搜索等功能  |
| PicGo + 阿里云 OSS        | 上传图片，生成可放进文章的图片链接          |
| Git + GitHub           | 记录修改，并保存网站源文件              |
| GitHub Actions + Pages | 在云端构建网站，再对外提供访问            |
| Giscus                 | 通过 GitHub Discussions 承载评论 |

日常流程是：**新建笔记 → 写作与插图 → 本地预览 → 提交并推送 → 自动构建发布**。

## 2. 准备项目与主题

先安装 Git、Hugo、Obsidian 和 GitHub Desktop。PicGo 如果已经能在 Typora 中上传图片，可以继续使用原配置。

在 macOS“终端”中检查：

 git --version  
 hugo version

对于本文使用的 [Hugo 0.159.2](https://github.com/gohugoio/hugo/releases/tag/v0.159.2)，Mac 安装包选择 `hugo_extended_0.159.2_darwin-universal.pkg`。它是命令行工具，安装后在终端使用；如果 Git 尚未安装，可按 macOS 提示安装命令行开发工具。

新项目可以这样建立；**已有项目跳过创建步骤，先在仓库外备份整个文件夹**：

 cd ~/Documents  
 hugo new site MyHomepage  
 cd MyHomepage  
 git init -b main

在项目根目录安装并固定 Stack 版本；已安装同一子模块时不要重复添加：

 git submodule add --depth=1 https://github.com/CaiJimmy/hugo-theme-stack.git themes/hugo-theme-stack  
 git -C themes/hugo-theme-stack fetch --depth=1 origin tag v4.0.3  
 git -C themes/hugo-theme-stack checkout --detach v4.0.3

项目中主要用到这些位置：

 MyHomepage/                  ← 项目根目录，运行 Hugo 命令的位置  
 ├── hugo.yaml                ← 网站配置  
 ├── .gitignore               ← Git 忽略规则  
 ├── .github/workflows/       ← 自动部署配置  
 ├── assets/img/avatar.jpg    ← Stack 头像  
 ├── assets/scss/custom.scss  ← 自定义样式  
 ├── static/fonts/            ← 自托管字体，可选  
 ├── content/                 ← Obsidian 打开的库  
 │   ├── notes/               ← 学习笔记  
 │   ├── posts/               ← 随笔文章  
 │   ├── _templates/          ← 新文章模板，不发布  
 │   ├── about.md  
 │   ├── archives.md  
 │   └── search.md  
 └── themes/hugo-theme-stack/ ← 主题子模块，不直接修改

“库根目录”在这里指 `content`；“项目根目录”指它上一级的 `MyHomepage`。私人笔记另建 Obsidian 库，放在博客仓库之外。

## 3. 配置首页、栏目和阅读样式

将头像放到 `assets/img/avatar.jpg`。新站的 `hugo.yaml` 可以从下面这份基础配置开始，先把 `YOUR_USERNAME` 换成自己的 GitHub 用户名。已有站点应对照合并，不要覆盖已填写的个人设置。

如果新项目自动生成了 `hugo.toml`，改用 YAML 前先将旧配置备份到项目外，避免同时维护两份主配置。下文所有路径均相对于 `MyHomepage`，缺少的文件夹需先创建。

 baseURL: "https://YOUR_USERNAME.github.io/"  
 title: "我的博客"  
 theme: "hugo-theme-stack"  
 defaultContentLanguage: "zh"  
 locale: "zh-CN"  
 hasCJKLanguage: true  
 timeZone: "Asia/Shanghai"  
 pagination:  
   pagerSize: 10  
 ignoreFiles:  
   - '(^|/)\.obsidian(/|$)'  
   - '(^|/)\.trash(/|$)'  
   - '(^|/)_templates(/|$)'  
   - '(^|/)_attachments(/|$)'  
 permalinks:  
   page:  
     notes: "/notes/:slug/"  
     posts: "/posts/:slug/"  
 taxonomies:  
   category: categories  
   tag: tags  
 params:  
   mainSections: [notes, posts]  
   sidebar:  
     subtitle: "记录学习、思考与成长"  
     avatar: "img/avatar.jpg"  
   article:  
     math: true  
     toc: true  
     readingTime: true  
   widgets:  
     homepage:  
       - type: search  
       - type: categories  
       - type: tag-cloud  
     page:  
       - type: toc  
   colorScheme:  
     toggle: true  
     default: light  
   comments:  
     enabled: false  
 menu:  
   main:  
     - {name: "首页", url: "/", weight: 10, params: {icon: home}}  
     - {name: "笔记", url: "/notes/", weight: 20, params: {icon: categories}}  
     - {name: "随笔", url: "/posts/", weight: 30, params: {icon: messages}}  
     - {name: "关于", url: "/about/", weight: 40, params: {icon: user}}  
     - {name: "归档", url: "/archives/", weight: 50, params: {icon: archives}}  
     - {name: "搜索", url: "/search/", weight: 60, params: {icon: search}}  
 markup:  
   goldmark:  
     extensions:  
       passthrough:  
         enable: true  
         delimiters:  
           block: [['$$', '$$'], ['\[', '\]']]  
           inline: [['$', '$'], ['\(', '\)']]  
     renderer:  
       unsafe: true  
   highlight:  
     noClasses: false  
 caches:  
   images:  
     dir: ":cacheDir/images"

`unsafe: true` 用于保留文章里的 HTML，例如后文的 `<img>`。这也意味着应只发布自己检查过的 HTML，不粘贴来源不明的脚本。公式配置参考 [Hugo Markdown 渲染设置](https://gohugo.io/configuration/markup/)。

新建 `content/about.md`，在文件头后填写简介、教育经历、项目和成果：

 ---  
 title: "关于"  
 url: "/about/"  
 draft: false  
 toc: true  
 comments: false  
 ---  
 ​  
 ## 简介  
 ​  
 在这里填写个人介绍。

新建 `content/search.md`：

 ---  
 title: "搜索"  
 layout: "search"  
 url: "/search/"  
 outputs: [HTML, JSON]  
 draft: false  
 comments: false  
 ---

新建 `content/archives.md`：

 ---  
 title: "归档"  
 layout: "archives"  
 url: "/archives/"  
 draft: false  
 comments: false  
 ---

文件应从 `---` 开始。搜索页不要设置 `build.list: never`，否则 Stack 的搜索组件可能找不到它。

`content/notes/_index.md` 和 `content/posts/_index.md` 分别设置 `title: "笔记"`、`title: "随笔"`，同样放在一对 `---` 中。年份、月份子文件夹不需要额外创建 `_index.md`。

字体与样式放在项目自己的 `assets/scss/custom.scss`，避免主题更新时覆盖修改。例如：

:root {  
  --base-font-family: -apple-system, "PingFang SC", sans-serif;  
  --article-font-family: "Songti SC", "STSong", "Noto Serif CJK SC", serif;  
  --code-font-family: "SFMono-Regular", Menlo, Consolas, monospace;  
  --article-line-height: 1.85;  
}

如果需要更统一的跨设备字体，可以将有合适许可证的 WOFF2 字体放进 `static/fonts/`，通过 `@font-face` 引用 `/fonts/文件名.woff2`，再填入字体变量。可选字体包括 [LXGW Bright](https://github.com/lxgw/LxgwBright)；保留其许可证。只指定系统字体时，不同设备的显示会有差异。

## 4. 用 Obsidian 管理公开笔记

在 Obsidian 中选择“打开本地仓库”，打开 `MyHomepage/content`，不是整个项目。建议关闭“使用 Wiki 链接”，优先使用标准 Markdown 链接，减少编辑器与网页之间的差异。

在项目根目录的 `.gitignore` 中加入：

/public/  
/resources/_gen/  
/.hugo_build.lock  
.DS_Store  
/content/.obsidian/  
/content/.trash/  
/content/_attachments/

Finder 默认隐藏点开头的文件，按 `Command + Shift + .` 可以显示。新建文件时确认名字是 `.gitignore`，不是 `.gitignore.txt`。忽略规则不会自动取消对已经提交文件的跟踪。

这里有两层排除：`.gitignore` 决定哪些文件不上传，Hugo 的 `ignoreFiles` 决定哪些内容不进入网页。`_templates` 可以提交用于备份，但不应生成为网站文章。

### 用 QuickAdd 快捷新建文章

安装并启用 QuickAdd，在 `content/_templates/blog.md` 中保存：

---  
title: '{{VALUE:文章标题}}'  
date: '{{DATE:YYYY-MM-DDTHH:mm:ssZ}}'  
slug: '{{DATE:YYYYMMDD-HHmmss}}'  
draft: true  
description: ''  
categories: []  
tags: []  
math: true  
toc: true  
comments: true  
---  
  
## 内容  
  
{{CURSOR}}

在 QuickAdd 新建一个 Template 类型的选项：

|设置|内容|
|---|---|
|模板路径|`_templates/blog.md`|
|文件名格式|`{{DATE:YYYYMMDD-HHmmss}}-{{VALUE:文章标题}}`|
|新建目录|`notes/{{DATE:YYYY}}/{{DATE:MM}}`|
|创建后打开|开启|
|覆盖已有文件|关闭|

将该选项添加为命令，再到 Obsidian 快捷键设置绑定组合键。若使用 `Command + N`，先解除默认“新建笔记”的同名快捷键。随笔可复制一份设置，将目录改为 `posts/...`。界面选项以所用版本为准，见 [QuickAdd 模板文档](https://quickadd.obsidian.guide/docs/Choices/TemplateChoice/)。

新建后检查标题、日期、目录和 `draft: true`。`slug` 决定文章网址，之后修改标题时保留它。标题中如有英文单引号，需要在 YAML 单引号字符串里写成两个单引号，或手动调整引号。

## 5. 图片上传、缩放与公式

### 复用 PicGo 和阿里云 OSS

先确认 PicGo 在 Typora 中仍能正常上传，再给 Obsidian 安装支持 PicGo 的图片上传插件。不同插件名称与设置项可能不同，不要同时启用多个自动上传插件。

开启 PicGo 的本地 Server，插件连接地址通常是 `http://127.0.0.1:36677/upload`，以 PicGo 实际端口为准。PicGo 需要保持运行，不必重新填写一遍 OSS 密钥。

分别测试粘贴截图、拖入图片。成功后，文章中应出现标准图片链接：

![图片说明](https://你的图床域名/图片路径.png)

若仍是本地文件路径或 `![[图片.png]]`，不能据此认定上传成功。自动上传失败时，可先用 PicGo 上传，再粘贴得到的 Markdown 链接。设置说明见 [PicGo 文档](https://picgo.github.io/PicGo-Doc/zh/guide/config.html)。

图床上传和博客发布是分开的：即使文章还是草稿，图片也可能已经可以公开访问。OSS 密钥不放进笔记或 Git 仓库；私有文件不要与公开博客图片混用访问权限，存储和流量也可能产生费用。

### 用百分比调整图片

Typora 常生成下面的 HTML，Hugo 允许原始 HTML 后也能使用：

<img src="https://你的图床域名/example.png" alt="图片说明" style="zoom:50%;" />

如果希望图片占正文宽度的一半并居中，可以改为：

<img src="https://你的图床域名/example.png" alt="图片说明"  
     style="width:50%;height:auto;display:block;margin:0 auto;" />

`zoom:50%` 缩放元素；`width:50%` 按所在容器的宽度计算，两者不是同一个含义。实际插图时直接写 HTML，不加代码围栏。Obsidian 的 `![说明|400](链接)` 不属于通用 Markdown 尺寸语法，不能假设 Hugo 会按同样方式处理。

### 公式

前面的配置已经开启 Stack 的数学渲染与 Hugo 公式透传。文章中可写：

行内公式：$E = mc^2$  
  
独立公式：  
$$  
\int_0^1 x^2\,dx = \frac{1}{3}  
$$

这不需要在 Mac 上安装完整 LaTeX。编辑器能显示不等于网页一定正常，应在 Hugo 预览中再检查一次。

## 6. 配置 Giscus 评论

在用于评论的公开 GitHub 仓库中开启 Discussions，安装 Giscus GitHub App，并只授权需要的仓库。打开 [Giscus 配置页](https://giscus.app/zh-CN)，选择仓库、讨论分类和按 `pathname` 匹配文章，取得对应 ID。

将 `hugo.yaml` 中原来的 `params.comments` 替换为以下结构。**整段缩进两个空格，放在已有 `params` 下面，不要再创建第二个 `params`**：

comments:  
  enabled: true  
  provider: giscus  
  giscus:  
    repo: "YOUR_USERNAME/YOUR_USERNAME.github.io"  
    repoID: "从 Giscus 配置页取得"  
    category: "Announcements"  
    categoryID: "从 Giscus 配置页取得"  
    mapping: "pathname"  
    strict: 1  
    reactionsEnabled: 1  
    emitMetadata: 0  
    inputPosition: "top"  
    lightTheme: "light"  
    darkTheme: "dark_dimmed"  
    lang: "zh-CN"  
    loading: "lazy"

分类名称和 ID 必须对应实际选择。文章文件头也应允许评论，即 `comments: true`。评论出现在文章详情页底部，不是首页文章列表；“关于”等页面可以单独关闭。若仍不显示，再检查 Giscus 网络请求和仓库授权，而不是反复粘贴评论脚本。

## 7. 发布到 GitHub Pages

创建名为 `YOUR_USERNAME.github.io` 的公开仓库，正式地址就是 `https://YOUR_USERNAME.github.io/`。已有这个仓库就继续使用，不要重复创建。

在 **GitHub Desktop 桌面应用**中选择 `File → Add Local Repository`，添加 `MyHomepage`。检查待提交文件，完成 Commit，再 Publish repository 或 Push origin。这个入口不在 GitHub 网页上。

若已在网页创建空仓库，而本地还没有 `origin`，可在项目根目录运行以下命令关联它；先替换用户名，已有 `origin` 时不要重复添加。新建远程空仓库时不勾选 README、许可证等初始化选项，可减少首次同步冲突。

git remote add origin https://github.com/YOUR_USERNAME/YOUR_USERNAME.github.io.git

仓库网页进入 `Settings → Pages`，将 Source 设为 **GitHub Actions**。在项目的 `.github/workflows/hugo.yaml` 中配置构建与部署；这个文件不同于根目录的 `hugo.yaml`。工作流可参考 [Hugo 官方 GitHub Pages 指引](https://gohugo.io/host-and-deploy/deploy-to-github-pages/)，已有可用工作流则保留。

核对四项即可：检出代码时递归下载主题子模块；Hugo 版本与本地一致；正式构建不带 `-D`；上传的是构建后的 `public` 目录。`public` 由 Actions 生成，不需要提交到源码仓库。

下面是一份对应本文固定版本的工作流，可保存为 `.github/workflows/hugo.yaml`。它监听 `main` 分支；已有项目若使用其他分支，应调整分支名。

name: Publish Hugo website  
on:  
  push:  
    branches: [main]  
  workflow_dispatch:  
permissions:  
  contents: read  
  pages: write  
  id-token: write  
concurrency:  
  group: pages  
  cancel-in-progress: false  
env:  
  HUGO_VERSION: "0.159.2"  
  TZ: "Asia/Shanghai"  
jobs:  
  build:  
    runs-on: ubuntu-latest  
    steps:  
      - uses: actions/checkout@v7  
        with:  
          submodules: recursive  
          fetch-depth: 0  
      - uses: actions/configure-pages@v6  
        id: pages  
      - name: Install Hugo  
        run: |  
          mkdir -p "${RUNNER_TEMP}/hugo-bin"  
          curl --fail --location --retry 3 \  
            "https://github.com/gohugoio/hugo/releases/download/v${HUGO_VERSION}/hugo_extended_${HUGO_VERSION}_linux-amd64.tar.gz" \  
            --output "${RUNNER_TEMP}/hugo.tar.gz"  
          tar -xzf "${RUNNER_TEMP}/hugo.tar.gz" -C "${RUNNER_TEMP}/hugo-bin"  
          echo "${RUNNER_TEMP}/hugo-bin" >> "${GITHUB_PATH}"  
      - name: Build website  
        run: hugo --gc --minify --baseURL "${{ steps.pages.outputs.base_url }}/"  
      - uses: actions/upload-pages-artifact@v5  
        with:  
          path: public  
  deploy:  
    runs-on: ubuntu-latest  
    needs: build  
    environment:  
      name: github-pages  
      url: ${{ steps.deployment.outputs.page_url }}  
    steps:  
      - uses: actions/deploy-pages@v5  
        id: deployment

下载地址中引用 `${HUGO_VERSION}`，不能写成 `${0.159.2}`。Actions 的构建机器通常是 Linux，因此云端下载 Linux 包，本机下载 macOS 包。新版官方示例的工具版本和安装步骤可能不同，不要只替换一个数字就混用。

首次推送后，在 Actions 中确认 build 和 deploy 都成功，再访问正式网址。Mac 上的 `localhost:1313` 只是本地预览地址，不是公开博客地址。

## 8. 自动保存版本，手动决定发布

在 Obsidian 安装 Git 插件。桌面端插件可以使用上级目录的 Git 仓库，因此不要在 `content` 内再运行 `git init`。也可以继续用 GitHub Desktop 完成提交和推送。

我采用“每 10 分钟本地提交，手动推送”的方式。设置名称随版本可能略有不同，目标是：

- 自动提交间隔：10 分钟。
    
- 自动 Push、自动 Pull：关闭；使用分钟数的选项通常设为 `0`。
    
- `Push on commit-and-sync`、`Pull on commit-and-sync`、`Pull on startup`：关闭。
    
- 合并策略使用 Merge，冲突策略保留默认；暂不开启推送前压缩提交。
    

先修改测试笔记，确认本地 Git 历史产生提交，而 GitHub Actions 没有被触发，再长期使用自动提交。设置含义可对照 [Obsidian Git 文档](https://publish.obsidian.md/git-doc/Start%20here)。

发布时，在 **Obsidian 中按 `Command + P`** 打开命令面板：

1. 打开 Git 的 Source Control 视图，检查待提交文件。
    
2. 执行 `Git: Commit all changes with specific message`，输入提交说明。
    
3. 执行独立的 `Git: Push`；若插件推送失败，可在 GitHub Desktop 中尝试 `Push origin`。
    

这些带 `Git:` 前缀的是 Obsidian 命令，不是要输入终端的文本。Push 会上传所有尚未推送的提交，不只当前打开的一篇文章。公开仓库中的草稿源文件和提交历史也可以被阅读，`draft: true` 不提供隐私保护。

## 9. 每次发文的检查顺序

1. 用 QuickAdd 新建文章，填写正文、分类和标签，插入图片与公式。
    
2. 确认文章、截图中没有密钥、私人信息或无权公开的内容。
    
3. 在终端进入项目根目录并启动预览：
    
    cd ~/Documents/MyHomepage  
    hugo server -D
    
4. 浏览器打开 `http://localhost:1313/`，检查文章、目录、图片与公式。
    
5. 发布前将文章的 `draft` 改为 `false`，确认 `date` 不是未来时间，保留固定 `slug`。
    
6. 回到运行 Hugo 的终端，按 **Control + C** 停止预览，再运行正式构建：
    
    hugo --gc --minify
    
7. 无构建错误后，检查修改、Commit、Push，等待本次 Actions 完成。
    
8. 手机打开正式网址检查新文章，并在文章底部测试评论。此时无需保持 Mac 的预览服务运行。
    

## 10. 搭建时遇到的几个问题

|现象|原因与处理|
|---|---|
|找不到 `book.svg`、`pencil.svg`|配置引用了主题未提供的图标。改用已有的 `categories`、`messages`，或自行补充 SVG。|
|`Search page not found`|检查搜索页的 `layout: search`；不要用 `build.list: never` 将它从主题查找范围中排除。|
|`Taxonomy categories not found`|还没有文章填写分类，可给测试文章加上 `categories: ["学习记录"]`；这是警告，不同于阻止构建的错误。|
|找不到 Hugo 配置|常见原因是在 `content` 内运行命令，返回 `MyHomepage` 再运行。|
|Actions 报 `bad substitution`|把版本号误写进了变量名。使用 `${HUGO_VERSION}`，在 `env` 中设置版本值。|
|文章没有评论|同时检查全局评论开关、文章 `comments`、Giscus 授权和网络；不要只在首页寻找。|
|图片尺寸在编辑器与网站不同|检查是否使用了编辑器专有语法、是否允许 HTML，以及缩放基准是元素还是容器。|
|推送报 `Failed to connect to github.com port 443`|网络连接超时，不是文章或主题错误。检查网络、代理和热点连接；浏览器能打开 GitHub 不代表 Git 使用相同网络路径。不要关闭 SSL 校验或重建仓库。|
|推送报 `self signed certificate in certificate chain`|Git 不信任收到的证书链。常见原因包括 HTTPS 解密代理、网络安全网关或证书配置异常。先换网络并对比 GitHub Desktop；不要直接关闭证书校验，也不要导入来源不明的证书。|
|文件旁边仍有 `M`|当前文件还有未提交修改。已有提交推送成功，也不代表这些新修改已经上传。|

排错时先分清失败发生在哪里：本地生成、Git 推送、Actions 构建，还是浏览器加载。每次只处理对应的一层，再重新验证。

证书错误不能仅凭提示确定来源。若使用单位管理的网络或设备，应联系管理员确认可信证书；自己的设备则先检查是否开启抓包或 HTTPS 解密。相关设置见 [Git 的证书校验说明](https://git-scm.com/docs/git-config#Documentation/git-config.txt-httpsslVerify)。推送失败不会删除本地文件或已有提交，但本次修改尚未因此发布。
